Ticket Management

מערכת Full Stack לניהול קריאות שירות, שפותחה באמצעות ASP.NET Core 8 בצד השרת ו־React עם TypeScript בצד הלקוח.

המערכת מאפשרת יצירה, צפייה, חיפוש, סינון, עדכון ומחיקה של קריאות שירות באמצעות ממשק משתמש פשוט ונוח.

## טכנולוגיות

### צד שרת – Backend
- **ASP.NET Core 8 Web API** – פיתוח ממשקי API.
- **C#** – שפת הפיתוח בצד השרת.
- **Entity Framework Core** – גישה למסד הנתונים.
- **SQLite** – מסד נתונים לשמירת קריאות השירות.
- **Swagger / OpenAPI** – תיעוד ובדיקת ממשקי API.
- **xUnit ו־Moq** – בדיקות יחידה ללוגיקה העסקית.

### צד לקוח – Frontend
- **React** – בניית ממשק המשתמש.
- **TypeScript** – פיתוח עם בדיקת טיפוסים.
- **Vite** – סביבת פיתוח ובנייה.
- **CSS** – עיצוב הממשק.
- **Fetch API** – תקשורת עם השרת.

## יכולות המערכת

- יצירת קריאת שירות עם כותרת, תיאור ורמת עדיפות.
- הצגת קריאות השירות בטבלה.
- חיפוש קריאות לפי כותרת.
- סינון לפי סטטוס ורמת עדיפות.
- עדכון סטטוס הקריאה: Open, InProgress או Closed.
- מחיקת קריאה לאחר אישור המשתמש.
- ולידציה של שדות חובה והצגת הודעות שגיאה מתחת לשדות.
- הצגת מצבי טעינה וטיפול בשגיאות.
- בדיקות יחידה ללוגיקה העסקית.

## ארכיטקטורת המערכת

צד השרת בנוי בארכיטקטורת שכבות תוך הקפדה על הפרדת אחריות (Separation of Concerns).

**Domain** – מכיל את הישויות, ה־Enums והחוקים העסקיים.

**Application** – מכיל את השירותים, הממשקים, מודלי הסינון והלוגיקה של המערכת.

**Infrastructure** – אחראי על הגישה למסד הנתונים באמצעות Entity Framework Core.

**API** – חושף את נקודות הקצה ומטפל בבקשות HTTP ובשגיאות.

צד הלקוח מחולק לקומפוננטות, Hooks מותאמים אישית, שכבת תקשורת עם ה־API ודפי תצוגה.


## הוראות התקנה והרצה

### דרישות מקדימות

- .NET 8 SDK
- Node.js ו־npm

### הפעלת צד השרת

מתיקיית הפרויקט הראשית:

```bash
cd backend
dotnet restore
dotnet run --project TicketManagement.Api --urls http://0.0.0.0:5000
```

לאחר הפעלת השרת ניתן לגשת ל־Swagger בכתובת:

`http://localhost:5000/swagger`

יש לוודא שמסד הנתונים אותחל באמצעות ה־Migrations של Entity Framework Core.

### הפעלת צד הלקוח

יש לפתוח טרמינל נוסף ולהריץ:

```bash
cd frontend
npm install
npm run dev -- --host 0.0.0.0
```

ממשק המשתמש יהיה זמין בכתובת:

`http://localhost:5173`

בסביבת הפיתוח, בקשות ל־`/api` מועברות לשרת באמצעות הגדרות ה־Proxy של Vite.

## ממשקי API

| Method | Endpoint | תיאור |
|---|---|---|
| GET | `/api/tickets` | שליפת קריאות שירות עם אפשרות לסינון |
| GET | `/api/tickets/{id}` | שליפת קריאה לפי מזהה |
| POST | `/api/tickets` | יצירת קריאה חדשה |
| PATCH | `/api/tickets/{id}/status` | עדכון סטטוס |
| DELETE | `/api/tickets/{id}` | מחיקת קריאה |

## בדיקות יחידה

הפרויקט כולל בדיקות יחידה באמצעות xUnit ו־Moq.

הבדיקות מכסות יצירת קריאות, ולידציה, שליפת נתונים, עדכון סטטוס, מחיקה וטיפול במקרים שבהם קריאה אינה קיימת.

להרצת הבדיקות:

```bash
cd backend
dotnet test
```

**תוצאת הבדיקה האחרונה:** 11 בדיקות עברו בהצלחה, ללא כישלונות.
